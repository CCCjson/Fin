# 整体架构设计文档

## 1. 系统概述

### 1.1 系统定位
个人量化交易工具（Quant Trading Platform）是一个面向个人投资者的多市场量化交易系统，支持 A股、港股、美股三大市场，提供数据获取、技术分析、策略回测、模拟交易和实盘交易的完整闭环。

### 1.2 设计目标
- **易用性**：Web 界面友好，降低量化交易门槛
- **扩展性**：模块化设计，支持自定义策略和指标
- **可靠性**：完善的错误处理和风控机制
- **性能**：支持实时数据处理和快速回测
- **安全性**：多层风控，保护资金安全

### 1.3 核心价值
- 统一多市场数据源，消除数据孤岛
- 标准化信号检测，提高决策效率
- 量化回测验证，避免主观臆断
- 自动化交易执行，减少情绪干扰

## 2. 架构设计原则

### 2.1 分层架构
采用经典的四层架构模式：

```
┌─────────────────────────────────────────┐
│         表现层 (Presentation)            │
│      React + TailwindCSS + Charts       │
└─────────────────────────────────────────┘
                    ↕ REST/WebSocket
┌─────────────────────────────────────────┐
│           应用层 (Application)           │
│         FastAPI + Business Logic        │
└─────────────────────────────────────────┘
                    ↕
┌─────────────────────────────────────────┐
│            领域层 (Domain)               │
│   Data | Analysis | Backtest | Trade    │
└─────────────────────────────────────────┘
                    ↕
┌─────────────────────────────────────────┐
│        基础设施层 (Infrastructure)        │
│    SQLite/DuckDB | Scheduler | Cache    │
└─────────────────────────────────────────┘
```

### 2.2 模块化设计
每个引擎独立封装，通过清晰的接口通信：

```
Data Engine ──→ Analysis Engine ──→ Signal Generator
     ↓                                     ↓
Storage Layer ←─────────────────── Backtest Engine
     ↑                                     ↓
Scheduler                           Trade Engine
```

### 2.3 设计模式应用
- **策略模式**：可插拔的交易策略
- **工厂模式**：数据源适配器工厂
- **观察者模式**：实时数据推送
- **单例模式**：数据库连接池
- **模板方法**：回测引擎流程控制

## 4. 技术栈决策

### 4.1 后端技术栈

| 技术领域 | 选型 | 理由 |
|---------|------|------|
| Web 框架 | FastAPI | 异步高性能、自动文档、类型检查 |
| 数据获取 | akshare/yfinance | 免费、稳定、覆盖多市场 |
| 技术分析 | pandas-ta | 纯 Python、易扩展、指标全面 |
| 回测框架 | vectorbt | 向量化回测、速度快、可视化好 |
| 数据存储 | SQLite + DuckDB | 轻量级、无需配置、分析性能好 |
| 任务调度 | APScheduler | 轻量级、支持 cron、内存型 |
| 日志管理 | loguru | API 简洁、自动轮转、彩色输出 |
| 类型检查 | Pydantic | 数据验证、自动序列化 |

### 4.2 前端技术栈

| 技术领域 | 选型 | 理由 |

| 框架 | React 18 | 生态成熟、组件化、Hooks |

## 5. 核心功能模块

### 5.1 数据引擎 (Data Engine)
**职责**：
- 从多个数据源获取市场数据
- 数据标准化与清洗
- 数据存储与增量更新
- 数据查询与缓存

**输入**：股票代码、时间范围、数据频率
**输出**：标准化的 OHLCV 数据

### 5.2 分析引擎 (Analysis Engine)
**职责**：
- 技术指标计算（趋势、震荡、波动率、成交量）
- 买卖信号检测
- 多股票批量筛选
- K线形态识别

**输入**：OHLCV 数据、指标参数
**输出**：指标数值、买卖信号、信号强度

### 5.3 回测引擎 (Backtest Engine)
**职责**：
- 策略回测执行
- 仓位管理模拟
- 交易成本计算
- 绩效指标统计

**输入**：历史数据、策略配置、初始资金
**输出**：回测报告、资金曲线、交易记录

### 5.4 交易引擎 (Trade Engine)
**职责**：
- 订单管理（创建、取消、状态跟踪）
- 模拟交易撮合
- 实盘交易对接
- 持仓管理
- 风险控制

**输入**：交易信号、风控参数
**输出**：订单执行结果、持仓状态

### 5.5 可视化层 (Frontend)
**职责**：
- K线图表展示
- 指标叠加与切换
- 信号标注
- 回测结果可视化
- 实时数据推送

**输入**：后端 API 数据
**输出**：交互式 Web 界面

## 6. 非功能性需求

### 6.1 性能要求
- API 响应时间 < 500ms (P95)
- K线图加载时间 < 1s (1000 条数据)
- 回测速度 > 1000 条记录/秒
- WebSocket 消息延迟 < 100ms
- 支持同时 10 个股票实时分析

### 6.2 可靠性要求
- 数据获取失败自动重试（3次，指数退避）
- 数据库操作异常回滚
- 关键操作日志记录（数据更新、信号触发、交易执行）
- 定期数据备份（每日凌晨）

### 6.3 安全性要求
- API Key 环境变量存储
- 交易操作二次确认
- 风控规则不可绕过
- 实盘模式需要密码验证
- HTTPS 通信加密

### 6.4 可维护性要求
- 模块化设计，低耦合
- 完整的类型注解
- 详细的文档字符串
- 单元测试覆盖率 > 70%
- 代码符合 PEP 8 规范

### 6.5 可扩展性要求
- 支持新增数据源
- 支持自定义技术指标
- 支持自定义交易策略
- 支持新增券商接口
- 配置化的参数管理

## 7. 风险与挑战

### 7.1 技术风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 数据源不稳定 | 数据缺失 | 多数据源冗余、离线缓存 |
| 实时数据延迟 | 信号滞后 | WebSocket 推送、本地缓存 |
| 回测过拟合 | 策略失效 | 样本外测试、参数敏感性分析 |
| 券商 API 限流 | 交易失败 | 请求限速、错误重试 |

### 7.2 业务风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 市场极端行情 | 大额亏损 | 硬编码风控、熔断机制 |
| 策略信号错误 | 错误交易 | 信号确认机制、手动审核 |
| 网络故障 | 无法交易 | 离线模式、手动兜底 |
| 数据质量问题 | 决策失误 | 数据校验、异常值过滤 |

### 7.3 合规风险
| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 数据使用协议 | 侵权风险 | 仔细阅读 ToS、非商业用途 |
| 交易监管要求 | 账号封禁 | 遵守券商规则、合理频率 |
| 个人信息保护 | 隐私泄露 | 本地存储、加密敏感信息 |

- 项目脚手架搭建
- 数据引擎开发（A股数据源优先）
- 数据库设计与实现
- 基础 API 框架

**交付物**：能够获取并存储 A股日线数据

### Phase 2: 分析能力 (2周)
- 技术指标计算模块
- 信号检测逻辑
- 前端 K线图表

**交付物**：能够展示 K线图并显示买卖信号

### Phase 3: 回测验证 (2周)
- 回测引擎实现
- 策略配置系统
- 绩效指标计算
- 回测报告页面

**交付物**：能够回测简单的均线策略

### Phase 4: 交易闭环 (2周)
- 模拟交易实现
- 风控模块

- 美股数据源

**交付物**：支持三大市场

### Phase 6: 优化与完善 (持续)
- 性能优化

- 策略库扩充

## 10. 总结

本架构设计基于以下核心思想：
1. **简单优先**：避免过度工程，优先满足核心需求
2. **模块独立**：每个引擎职责清晰，便于测试和维护
3. **数据驱动**：所有决策基于数据，可追溯、可验证
4. **风险可控**：多层风控，保护资金安全
5. **逐步演进**：按阶段开发，快速验证价值

该架构为个人量化交易提供了一个坚实的技术基础，既保证了系统的专业性，又控制了开发复杂度，适合个人投资者快速上手并持续迭代。
