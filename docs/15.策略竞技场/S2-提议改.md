# S2 提议改

> ## ⚠️ 复审揪出的四个 major（都已修，写在这防重犯）
>
> ### 1. 🔴 过期提案会**静默回滚**刚批准过的改动
> 提案的 `base_strategy_id` 和 `diff` 冻结在提出那一刻。同族两份未决提案时：
> ```
> P1(tick 30→15) 批准 → v2: tick=15
> P2(单笔 100→800，基于 v1) 批准 → v3: **tick 被还原成 30**、单笔=800
> ```
> 而 P2 的确认框只显示「单笔 100 → 800」，**一个字都不提 tick 被改回去了**。
> → `proposals.staleness()` 在 preview **和** 工具函数里各拦一道（preview 只在走确认门时跑，
> 直接调函数绕得过去）；批准一份的同时把同族其它 `proposed` 标 `superseded_by_newer`
> —— 那个状态原本只写在注释里、**全仓没有任何代码写入**。
>
> ### 2. 🔴 `retire()` 会删掉 `EXECUTING`/`STALE` 的待确认单
> 直接违反 `pending.py` 里写死的禁令「搁浅的 EXECUTING 绝不能删、也绝不能当失败」。
> Jason 点了确认、币安调用在途时退役该策略 → 行被删 → `_finalize()` 找不到行静默 no-op、
> `cleanup()` 再没机会标 STALE 发对账告警 —— **一笔可能已在币安成交的真单，本地线索归零**。
> → 只删 `PENDING`，在途的原样留着并在返回里点名 + 告警。
>
> ### 3. 🔴 `latest_only` 把**正在跑的那一版**从交易中心藏起来
> v1 armed 正在排真单、AI 刚 apply 出 v2(draft) → 列表只剩 v2。Jason 打开 App 看到一条
> 未启用的草稿，那条真在下单的 v1 看不到、pause 不了、retire 不了。
> → 「每 family 最新版」**并上**「所有 `enabled=1` 的行」。
>
> ### 4. 🔴 `mode` 进 diff → 几乎每次 arm 预览都冒假的 🔒 告警
> `mode` 是**运行态**不是策略配置（`arm()` 无条件写 live、`enable_paper()` 无条件写 paper），
> 拿 armed 的 v1 比 draft 的 v2 永远得到「🔒 运行模式：live → paper」，而 arm 完立刻就是 live。
> 🔒 的全部价值在于它很少出现，每次都亮等于训练 Jason 无视它。→ `mode` 整个不进 diff。
>
> ### 另修（minor）
> - `enable_paper()` 绕过「同 family 最多一个在跑」→ 抽 `_supersede_siblings()` 两处共用
> - `family_id` 可为 NULL 时让位查询空转 → 加 `strategy_id == family` 兜底支
> - `fork_version` 的版本号在回测**之前**取 max → 挪进插入的同一个 session（那个索引不是唯一索引，DB 不挡）
> - `arm()` 不拦 `retired` → 加 `_assert_armable()`
> - `standings()` 缺版本号（多版本同名分不清）+ 退役版本永久累积 → 带 `version/family_id`，默认不列已归档
> - 血缘只在返回值里 → 加 `forked_from` 列
> - 迁移测试是**手抄一遍 SQL 再断言**，`init_db` 的 ALTER 分支从没被执行过
>   （根 conftest 用 `create_all` 建库，列天生就有）→ 改成手工建缺列的老表再让 `init_db` 去补
> - 前端 `superseded` 没样式（渲染成跟 armed 一样）、看不到版本号 → 补上
>   ⚠️ **改了前端，要跑 `bash restart.sh` 才生效**（App 没有热更新）

> **一句话**：现在 `compile_crypto_strategy` **只能从零编一条新策略，改不了现有的**。
> 这张卡把「AI 提议怎么改 → Jason 审 → 落成新版本 → 上线」这条链路补齐，
> 并让每份提案带上**可证伪断言**（预期收益 / 预期胜率），S4 拿真实盈亏给它打分。

## 1. 开工前探查（2026-07-27 逐条当场验过）

| 现状 | 影响 |
|---|---|
| `CryptoStrategy` **没有版本号** | 改一次就覆盖，「改完变好了没」无从对比 |
| `compile_and_persist` 永远 `_gen_id()` 新建 | AI 只会「再编一条」，两条策略之间没有血缘 |
| 🔴 `service.retire()` = **彻底删除**（连 `crypto_strategy_runs` 一起 `delete`） | 退役即失忆。S1 的战绩、S3 的历史对比全没了 |
| 🔴 `arm()` **只有 HTTP route，没有 agent 工具** | AI 确实 arm 不了（安全），但 `00-PLAN §1.2` 说的「代码承载物 = arm 走 `requires_confirmation=True`」**这东西还不存在** |
| `spec_from_row` / `_spec_to_columns` 已是干净的双向序列化 | 版本化可以直接复用，不用重写 |

### 1.1 三条裁决（2026-07-27 Jason 拍板）

1. **新版本 = 新行 + `family_id`**（不是「单行 + 版本历史表」）。
   理由：`crypto_strategy_runs` 和 `CryptoTrade.source_ref` **都是按 `strategy_id` 链的**，
   一个版本一行 → 战绩天然跟着版本走，「v1 vs v2 谁强」直接就是两条策略比 ——
   **这正好是 S3 竞技场要的形状**。反之单行方案要给 runs 和 trades 各加一个 version 字段。
   代价：策略列表会变长 → 默认只列每个 family 的当前版本。
2. **`retire` 改成软退役**：置 `status=retired` + `enabled=0` + 清待确认单
   （那些**必须**清，留着会误成交），**但保留 `crypto_strategy_runs`**。
   另给一个显式的「彻底删除」入口。
   理由：AI 提案样本一年才 12-24 条（`00-PLAN §4` 问题 2），删一条少一条。
3. **补 `arm_crypto_strategy` 工具**（`requires_confirmation=True`），
   让「策略变更必须人工审核」这条约束真的有代码承载物。

## 2. 提案的形状

`00-PLAN §3` 裁决 12（Jason 原话）：**目前策略的不足 / 想怎么调整 / 为什么 /
预期收益是多少 / 预期胜率是多少**。裁决 13：后两项让提案成为**可证伪断言** ——
这是整个计划最漂亮的一环，**拿账户余额给 AI 打分**。

### 2.1 提案带的是**完整新 spec**，不是 patch

AI 已经会写 `CryptoStrategySpec`（`compile_crypto_strategy` 就在干这个），
让它再学一套 JSON-Patch 语法只会增加出错面。

⭐ **但 diff 由我们确定性算出来**（`_diff_specs(old, new)`），不让 AI 描述自己改了什么 ——
它可能说漏、说错，而 Jason 要审的正是「到底改了哪几个数」。
这也是裁决 3 那句「提案不要是代码细节」能落地的原因：**diff 是「RSI 阈值 30→25」，
不是 code diff。**

### 2.2 三个动作，确认门只挂在后两个

| 工具 | 动作 | 确认门 | 为什么 |
|---|---|---|---|
| `propose_strategy_change` | 落一条提案 | ❌ 不需要 | 提案不动策略、不动钱，只是一段有结构的话。给它挂确认门等于让 Jason 为「AI 想说句话」点两次 |
| `apply_strategy_proposal` | 生成新版本（draft，**不自动上线**） | ✅ | 这是「策略变更」 |
| `arm_crypto_strategy` | 新版本上 live | ✅ | 这是「策略上线」，`00-PLAN §1.2` 第 1 条的承载物 |

⛔ **apply 之后绝不自动 arm。** 生成新版本落 `draft`/`backtested`、`enabled=0`，
旧版本**原样继续跑**。只有 Jason 显式 arm 新版本时，同 family 的旧 armed 版本才被
置 `superseded` + `enabled=0`。这样「批准了提案」和「让它上线」是两个决定。

### 2.3 ⚠️ 新增受确认门的工具必须登记

`common/decision_kind.py::CONFIRMED_TOOL_KINDS` ——
`apply_strategy_proposal` / `arm_crypto_strategy` 都记 `ops`（编策略/上线策略不是下单，
连价格都没有）。漏登记 `tests/test_decision_entry_kind.py` 会红。
