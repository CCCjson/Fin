## 2. 🔴 实锤修正：**「策略赚了多少」现在算不出来**

讨论阶段说过「数据现成，可立刻开工」——**这句话对一半**。

### 2.1 `pnl_realized_today` 不是这条策略的盈亏

```python
# crypto_intel_engine/cost_basis.py:421
def realized_on(day: date) -> float:
    """某个 crypto 市场日（UTC）的已实现盈亏。喂引擎当日回撤熔断。"""
    return sum(c["pnl"] for st in replay().values()          # ← 遍历**所有** symbol
                        for c in st["closed"] if c["date"] == key)
```

它是**整个账户**的当日已实现盈亏，`engine.py:420` 把它原样填进 `pnl_realized_today`。

**用于熔断是对的**（账户级回撤本来就该看账户）。**拿它当「这条策略赚了多少」是错的** ——
如果同时有卫冕者在下单 + Jason 在 MoneyBill 手动下单 + 待确认单成交，
**它们的盈亏全混在同一个币安账户里**。

⛔ **别看到这个字段名就直接拿来当策略收益用。** 这是本卡最容易踩的坑。

### 2.2 但归因是可行的——钥匙是 `order_id`

```
crypto_strategy_runs.executed_order_ids   （JSON: 币安 orderId 列表）
        ↓ join
CryptoTrade.order_id                       （成交价 / 量 / 手续费 / trade_date）
        ↓ 买卖配对（cost_basis.replay() 已有配对逻辑，复用别重写）
    这条策略的已实现盈亏
```

### 2.3 ⚠️ paper 和 live 是两条不同的路

模型注释写死了：**「paper 模式只写本表不写 CryptoTrade（保持真实连亏台账干净）」**。
这个隔离是**刻意的、正确的**，别去改它。

后果是两条路径要分别实现：

| 模式 | 盈亏来源 | 性质 |
|---|---|---|
| `live` | `executed_order_ids` → `CryptoTrade` → 真实成交价/手续费 | **真金白银** |
| `paper` | `decision_detail` 里的模拟撮合价 | **理想撮合**：挂单必成交、零冲击成本 |

⛔ **这两个数字不可直接比大小**——这正是 `00-PLAN §3` 裁决 9 的「坑 1」。
本卡只负责**算出来并标清楚是哪种**，比较规则留给 S3。

### 2.4 ⭐ 与 S4 的归因合并（**别建两套**）

S4 要做的「这笔单是 AI 建议还是 Jason 自主」，和本卡要做的「这笔成交属于哪条策略」，
**是同一个问题的两个切面**：一笔交易是从哪儿来的。

→ **建议设计一个统一的「交易来源归因」，一次做对**：

```
来源 = 策略（哪条 / 哪个版本） | AI 建议（哪条 decision） | Jason 自主 | 手动补录
```

开工 S1 时先把这个形状定下来，S4 直接复用。**分两次建必然长歪。**

## 3. 要做什么

### 3.1 引擎层：策略战绩计算

新增 `crypto_strategy/performance.py`（纯计算，不出网、不碰 LLM）：

- `strategy_pnl(strategy_id, *, since, until) -> dict` —— 按 §2.2 归因后的盈亏
- `strategy_health(strategy_id) -> dict` —— 体检：
  - **触发情况**：评估了多少 tick、开了几单、多少次被拦（按 `status` 分桶）
  - **没开单的原因分布** ← 这是最有信息量的一段（`blocked_cost` 占 80% = 成本吃光边际）
  - **盈亏**：已实现 / 手续费 / 净额，**标注 paper 还是 live**
  - **风险**：最大回撤、连亏 streak、护栏触发次数
  - **对比**：与它自己上一版、与当前卫冕者

### 3.2 工具层：MoneyBill 能问

新增 `agents/tools/crypto_strategy_tools.py` 里两个工具（该文件已存在）：

| 工具 | 回答什么 |
|---|---|
| `get_strategy_performance` | 「我那条 BTC 策略最近怎么样」——单条策略的完整体检 |
| `list_strategy_standings` | 「我现在有哪些策略、哪条最好」——竞技场排行（S3 会扩它） |

⚠️ **必须归组 `backend/agents/tool_groups.py`**，否则首次会话直接 RuntimeError
（`00-PLAN §2` 铁律第 2 条）。

### 3.3 输出要「自解释」

对齐 `00-PLAN §3` 裁决 16。工具返回的不只是数字，还要带人话结论：

```
❌  {"blocked_cost": 47, "orders_placed": 3}
✅  {"blocked_cost": 47, "orders_placed": 3,
     "verdict": "50 次评估里 47 次因为往返成本吃光了净边际而没开单——
                 这条策略的边际太薄，不是行情不好"}
```

理由同裁决 16：**这套东西只服务 Jason 一人，所以它必须解释。**
