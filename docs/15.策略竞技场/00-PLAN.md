## 0. 这份计划是什么

把 AI 从**每笔交易的热路径**，挪到**策略迭代的冷路径**。

```
旧：AI 给单笔建议 → Jason 逐笔审核 → 手动执行
                    └─ AI 在每一笔上被调用，大量调用产出零信息（实测 HOLD 占多数）

新：Jason ──审核策略变更──▶ AI ──提议/调整──▶ 策略 ──▶ 自动引擎 ──▶ 交易
     ▲                                                                │
     └──────────────── 真实盈亏 feedback ─────────────────────────────┘
```

**Jason 原话**：「我去监控 AI 行为，AI 自动调整交易策略，自动交易引擎自动化地执行交易策略，
返回交易结果以及收益给到 AI 去 feedback，然后调整交易策略」
「**其实我觉得很多行为不需要 AI，完全就是浪费**」

后面这句是本计划的第一性原理：**AI 只做只有 AI 能做的事，其余交给规则。**

## 3. 裁决清单（**⛔ 别再重推，要推翻先读理由**）

### 架构

1. **AI 的产出物 = 策略，不是单笔建议。**
   理由：单笔建议天然需要人二次决策 → 天然会悬空。实测 33 条 advice 无一条能追踪到落地。
   策略触发即执行，落地率天然 100%。

2. **AI 从热路径移到冷路径。**
   理由：Jason 原话「很多行为不需要 AI，完全就是浪费」。实测 `crypto_cockpit` 10 条留痕里
   6 条是 HOLD、confidence 47-50 分——几乎全是「没意见」，烧了算力产出零信息。

3. **策略形态用 DSL（声明式 JSON），不用 Python 代码，绝不用 C++。**
   理由（三条，最后一条最重要）：
   - C++ 改一次要重新编译 → 「AI 提议改策略」直接废掉；生成出错是段错误不是异常；无法沙箱
   - 代码形态无法上结构化护栏、无法做 degraded 判定
   - ⭐ **Jason 明确要求提案「不要是代码细节」**——代码形态的策略，提案必然是 code diff，
     那是审不动也不该审的东西。**只有 DSL 能让提案变成「RSI 阈值 30→25，因为…」这种人话。**

4. **C++ 只留在回测内核。**
   理由：策略逻辑完全不吃性能（30 分钟一 tick、几十个条件比较 = 微秒级）。
   吃算力的是回测（几年历史 × 几百标的 × 参数网格），**那一层已经是 C++ 了**。

5. **`alpha_lab` 退回它该待的位置**：做策略研究/参数搜索，产出**喂给 DSL**，
   不再直接产出上线代码。

### 策略竞技场

6. **组合策略 = 读法 A**：一条策略内部可含多个子策略 + 权重（如 60% 趋势 + 40% 均值回归），
   **整体算一条**。⛔ 不是「多条策略同时 live 各分资金」（读法 B，与「只有一条 live」矛盾，
   且要处理多策略对同一标的下反向单，复杂度高一个量级）。

7. **同一时期只有一条 live（卫冕者），其余全在 paper（挑战者）。**

8. **⭐ Jason 手写的策略永久置顶，作为基准线。**
   理由：**没有基准线的胜率是自说自话。** 如果只有 AI 能写策略，就永远不知道 AI 有没有价值。
   AI 长期输给随手写的双均线 → 这个数字最刺眼，也最该被看见。

9. **切换要过四道硬门槛，不是简单比收益率**（详见 S3 卡）：
   ① 观察期够长（≥N 天 **且** ≥M 笔触发）② 优势显著（超噪声范围，**挑战者越多线越高**）
   ③ `backtest_passed=1` ④ 风险不劣化（最大回撤）
   **另加冷却期**（切换后 X 天内不再换，防反复横跳吃双份手续费）。

   四个必须防的坑（量化经典送命题）：
   - **paper 与 live 不可比**：paper 是理想撮合（挂单必成交、零冲击）
   - **多重比较**：同时跑 10 条，最好的那条大概率是运气；跑越多偏差越强
   - **追逐近期最优 = 追涨杀跌的策略版**：换过去往往正是旧策略均值回归的起点
   - **收益率是错的指标**：会系统性选出高杠杆高波动的，该看风险调整后收益（Sharpe/Calmar）

10. **⭐ 规则判「切不切」，AI 判「为什么」和「下一条试什么」。**
    理由：四道门槛全是纯量化判定（比 Sharpe、算标准误、数笔数、查冷却期），
    规则引擎几行就够，**让 LLM 判反而更慢更贵还不稳定**（同样数据可能给出不同答案）。
    AI 该干的三件事：① 解释卫冕者为什么开始失效 ② 造新的挑战者
    ③ **对规则提出异议**（「数字上该切了，但这是财报季噪声，建议再观察两周」）

11. **「卫冕者变弱」与「挑战者变强」是两个独立触发，前者更紧急。**
    后者走四道门槛慢慢来；前者立刻降级（退 paper 或空仓），哪怕没有挑战者接位。
    ✅ 基础设施已有：`guardrails` + `paused_by_guardrail` + `consecutive_guardrail_trips`，
    缺的只是「失效之后让位给谁」。

### AI 提案

12. **提案格式（Jason 原话）**：目前策略的不足 / 想怎么调整 / 为什么 / **预期收益是多少** / **预期胜率是多少**。

13. **⭐ 后两项让提案成为可证伪断言**——这是整个计划最漂亮的一环：
    ```
    提案：均线 20→10，预期 30 天 +8%、胜率 55%
      ↓ Jason 批准，跑 30 天
    实际：+3%、48%  →  AI 这次判断记一次 miss
    ```
    **这是直接拿账户余额给 AI 打分**，比「cockpit 说 BUY 后来涨没涨」跟钱的关系近得多。

14. **提案入 `DecisionLog`，但需要新的评估层**——它没有 symbol、没有 entry_price，
    `common/outcome_eval.py` 的形状对不上。⛔ 别硬塞进 outcome_eval。
    （策略**触发的单个信号**倒是能直接喂 outcome_eval，那个形状是对的。）

### 交易终端

15. **面板系统，不写死布局。**
    理由：Jason 说「一屏塞多个面板我觉得有可能需要」「其他的后续按需求来」——面板会一直加。
    写死布局每加一块要改代码调 CSS；面板系统 = 注册 widget 即出现，拖拽/折叠/增删由 Jason 定。

16. **⭐ 设计铁律：面板数量不设限，但每个数字必须自解释。**
    Jason 原话「**太复杂了我也看不懂**」。判定标准：屏幕上任一数字，若 3 秒内说不出
    「所以我该干嘛」，就不配待在一级界面。
    ```
    ❌  Sharpe 1.42    最大回撤 -8.3%
    ✅  Sharpe 1.42 ↑ 比你手写的双均线强 40%
        最大回撤 -8.3% · 还在安全线内（护栏 -15%）
    ```
    **彭博不解释，因为用户是专业交易员。这个终端只服务 Jason 一人，所以它必须解释。**

17. **MoneyBill 就是我们的命令行。**
    彭博的灵魂是命令行（`AAPL US Equity GO`），我们已经有了，还是自然语言的。分工：
    **终端负责「看」（状态/盈亏/排行/待办），MoneyBill 负责「问」和「做」。**
    终端上任何一块看不懂 → 直接问 MoneyBill。这也正是「仅次于 MoneyBill」的含义：第二块屏，不是替代。

18. **全市场进来，预留市场切换 + 实时跳动。**
    ⚠️ 两个节奏要共存：crypto 7×24／30 分钟一 tick；A 股一天一次还要处理「已收盘」；
    港美股又是另一个时区。**终端上要能一眼看出「这个市场现在是开着还是睡着」。**

## 4. 🔴 四个真问题（审查发现，都改了路线）

### 问题 1：组合回测引擎不存在，且卡在关键路径上

```python
# crypto_strategy/backtest_gate.py:164  —— 实测
for symbol, bars in bars_by_symbol.items():
    res = run_bt(bars, signals, initial_capital=initial_capital, ...)
    #                            ↑ 每个币都假设有完整的一份本金
```

**多标的回测 = 逐币独立跑再聚合，不是真组合回测。** 没有资金竞争、没有「A 占了钱 B 就买不了」。
`run_crypto_backtest` 签名就是 `symbol: str`；C++ 引擎同样只跑单票。

**对裁决 6（组合策略）是致命的**：60% 趋势 + 40% 均值回归，逐票独立跑出的数字**跟权重毫无关系**。

→ 🔀 **2026-07-27 更正**：写 S3 卡时核实发现，它**不是 S3 的前置** —— 四道门槛要的是
「每条策略的日收益率序列」，从 S1 的归因数据就能算；组合回测是**裁决 6「组合策略」**的前置，
而那个功能在 DSL 里**根本还不存在**（`CryptoStrategySpec` 没有子策略也没有权重）。
→ 已拆出为 **S8**。且 Jason 拍板走**改 C++ 引擎支持多标的**这条路，
不在 Python 里重建回测层（「回测只剩 C++」这条决定保持不变）。

### 问题 2：AI 提案胜率可能永远达不到统计显著

策略变更一个月 1-2 次 → 一年 12-24 条提案，而 P0-3 的校准门槛是 **≥30 样本**。
「AI 的策略提案准不准」这个数**可能要 2-3 年**才有统计意义。

→ **处置**：① paper 池每条策略都算样本（并行 N 条 = 样本快 N 倍）
② 明确定位成**定性参考**而非统计结论，别在 UI 上摆一个永远是 `null` 的胜率。
