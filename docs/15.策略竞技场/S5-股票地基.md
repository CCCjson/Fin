# S5 股票地基

> **一句话**：crypto 那套「DSL → 引擎 → 版本化 → 竞技场 → 战绩」是完整的，
> 股票**一样都没有**。这张卡把那套抽成**市场无关的公共层**，
> 让股票策略能跟 crypto 策略同台竞技。

### 0.2 ⭐ 分析卡的形状（DSL 字段要从这里取）

`CockpitAggregator.aggregate(symbol)` 返回：

```
composite / raw_composite / recommendation / dimension_coverage / adjustments
price.{latest, change_5d_pct, change_20d_pct}
valuation / dynamic_levels
dimensions.{technical, fundamental, sentiment, ml, position}.{score, detail}
current_position.{shares, value, pct}
suggested / data_quality / total_capital / available_cash
```

⭐ 与 crypto 的 `analyze_crypto_symbol` **形状高度同构**（都有 composite /
recommendation / dimensions / price / 仓位），所以 DSL 的条件树可以直接复用，
**只有字段注册表（`FIELD_RESOLVERS`）需要按市场分叉**。

### 0.3 🔴 两个字段是陷阱，DSL 要么别暴露、要么标死

| 字段 | 问题 |
|---|---|
| `dim.ml` | `_score_ml` 在**没有训练模型时返回 None**，而这个项目**一个训好的模型都没有**（P1-6 未开工）。暴露它 = 邀请 AI 写出永远不触发的规则 |
| `dim.fundamental`（港股） | 港股财务数据恒缺 —— 但 Jason 已拍板**港股不做**，此条搁置 |

### 0.4 A 股特有的三条规则，实盘引擎必须全对

1. **T+1**：当日买入次日才可卖。`BrokerPosition.available` 已有这个概念，
   但 `PaperBroker` 明写「Paper Trading 没有 T+1 限制」—— 全自动跑之前必须补上，
   否则纸面成绩会系统性优于实盘。
2. **涨跌停**：封板时挂单成交不了。`common/limit_rules.py` 有判定，但**执行层还没用它**。
3. **100 股一手**：C++ 回测侧 S8 已经处理（`MarketRules::a_share()`），实盘侧要对齐。

⚠️ 美股三条都不适用（T+0、无涨跌停、1 股一手），所以这三条必须**按市场分叉**，
⛔ 别写成全局常量。

## 1. Jason 的四条拍板（2026-08-02）

1. **全自动交易** —— 「人仅负责监控交易历史和策略实施，其他的不干涉」。
   ⚠️ 这与 crypto 的**半自动（逐笔确认）**形成不对称，是刻意的，见 §1b。
2. **执行层先建地基，券商后接** —— 写完整的自动链路（tick → 风控 → 下单 → 回填成交），
   先接 `PaperBroker` 跑通，真券商当**可插拔后端**另卡接。
3. **共用一套，不另建** —— 把 crypto 那套抽成市场无关的公共层，
   ⚠️ 会动到正在跑真钱的 crypto 代码，回归风险要用测试兜住。
4. **先做 A 股 + 美股**，港股不做。

### 1b. ⚠️ 「股票全自动、crypto 半自动」这个不对称要记住

Jason 2026-07-21 特意把 crypto 从全自动**退回**半自动（逐笔确认），
2026-08-02 又要求股票**直接上全自动**。两者都是他的决定，不矛盾 ——
2026-07-27 的口径已经改成「**审策略变更，不审每笔**」。

🔒 但下面这些**一条都没放开**：
- 总持仓 ≤ 80%（必须留 20% 现金）
- 单日亏损 ≤ 3% 触发停止交易
- 每笔必须设止损
- 连亏 3 次暂停一天
- `agents/confirm_gate.py`：AI **不能自行 arm** 一条策略上线

⭐ 外加 Jason 选的一条：**新策略必须先 paper 跑一段才能 arm 到 live**
（与 crypto 的护栏同构）。

## 2. 设计

### 2.1 公共层怎么抽（不做大爆炸重构）

⛔ **不**把 `crypto_strategy/` 整体搬家 —— 那是正在跑真钱的代码，一次性重构的
回归面太大。改成**沿着接缝分层**：

| 抽出来 | 为什么它是市场无关的 |
|---|---|
| `Condition` / `ConditionGroup` / `evaluate()` | 纯粹的「取值 + 比较」，跟标的是什么毫无关系 |
| `RuleSet` / `rule_sets()` / 权重语义 | S8 刚建，本来就是市场无关的 |
| 版本化（family/version/软退役）| 「一条策略的第 N 版」跟市场无关 |
| 竞技场四道门槛 | 纯统计（日收益序列 → 显著性/回撤/冷却）|
| 提案 + 后验打分 | 同上 |

| 留在市场层 | 为什么 |
|---|---|
| `FIELD_RESOLVERS` | 分析卡形状不同（crypto 有资金费率，股票有估值/财务）|
| 执行器 | 下单通道、T+1、涨跌停、每手股数 |
| `CostModel` 默认值 | 费率结构完全不同（A 股有印花税，crypto 没有）|

### 2.2 全自动执行链

```
调度 tick → 分析卡 → DSL 评估 → 硬风控闸门 → 交易单位换算 → broker.submit_order
                                                              ↓
                                              回填成交 → 归因写台账（S1 那套）
```

🔒 **风控闸门不可绕过**，且必须在**下单之前**：`trading_engine/risk/adapter.py`
那三条（总仓位/单日亏损/止损）+ 连亏暂停。
⚠️ `max(总仓位上限, 单股上限)` 那个**静默撤销现金保护**的坑已经被复制过三份
（adapter / position_sizing / cockpit），⛔ 新写的执行器**绝不许出现第四份**，
有 AST 门禁盯着。

### 2.3 券商可插拔

`BaseBroker` 已经是抽象类（`submit_order/get_positions/get_account_info/...`）。
S5 只依赖这个接口，真券商到位时新增一个实现即可。
⛔ 执行器里**不许出现任何具体券商的名字**。

## 3b. 实施记录

### 批次 1：DSL 按市场查表

接缝比预想干净 —— 条件树本来就是市场无关的，绑死 crypto 的只有字段注册表。

🔴 **这批真正的价值是堵死一种失败模式**：DSL 的语义是「取不到值 = 不满足」，
所以一条 A 股策略写了 `funding_rate` **不会报错**，它会**静默永不触发**，
看上去像「行情一直没到条件」。现在编译期就拦，且报错说得清是哪个市场的字段。

同理挪走了 `Universe` 的 `.BN` 后缀校验（那是 crypto 假设，会让股票策略连编译都过不了），
改到 spec 层走 `infer_market_from_symbol` 判。

⛔ `dim.ml` 刻意不给股票（没有任何训练好的模型，暴露它 = 邀请写永不触发的规则）。
⛔ 港股不注册（Jason 拍板不做，真要跑直接抛而不是拿 A 股的表凑合）。

### 批次 2：交易规则收口 + 全自动执行链

**收口的理由不是消除重复，是防「A 股规则被套到美股头上」** —— 美股 T+0、
无涨跌停、1 股一手，三条全不适用，套错会**莫名其妙买不进也卖不掉且不报错**。

🔴 顺手拆掉一个真 bug：`PaperBroker` 把当日买入无条件标成可卖（注释还写着
「Paper Trading 没有 T+1 限制」）。于是纸面能当天来回做 T 而实盘做不到 ——
**纸面成绩系统性优于实盘**，而 Jason 定的护栏「新策略先 paper 跑一段再上实盘」
判断依据正是那个纸面成绩。等于用一把偏乐观的尺子把关。

执行器的**闸门顺序本身就是主要设计**：风控必须排在取整和封板判定**之后**、
紧挨着下单 —— 按「策略想要的量」判会漏，取整和封板都会改变实际下单量。

### 批次 3：市场落库 + 回测闸按市场分叉

🔴 `market` 没落库是**跟 `sub_strategies` 一模一样的坑**：存进去是股票策略、
读回来是 crypto → 所有条件取不到值而静默永不触发。已加列 + 自动迁移（存量回填 crypto）。

回测闸的 `market` 决定 C++ 侧的**费率**（A 股有印花税）和**交易单位**（100 股一手）。
⛔ 写死 crypto 的话，股票策略回测出来的净收益是假的，而那正是 arm 前的准入判据。
价格缩放也改成**只对 crypto**（股票本来就按股交易，缩放会让 `trades[].price`
变成没人看得懂的数）。

## 4. 验收

- 一条股票策略能被 DSL 表达、能过组合回测闸、能 paper 跑出成绩
- 🔒 硬风控四条在自动链路上**全部生效**，且有测试证明「绕不过去」
- A 股：T+1 生效、封板不成交、下单量是 100 的整数倍
- 美股：T+0、无涨跌停、1 股一手 —— **不许套用 A 股规则**
- ⛔ `dim.ml` 要么不暴露，要么在 DSL 描述里标死「当前恒缺，写了也不会触发」
- crypto 现有测试**一条都不许红**（公共层抽取的回归防线）
- ⚠️ **改完必须 `bash restart.sh`**
