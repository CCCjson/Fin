### 13.2b「接引擎」—— ❌ 撤销（2026-07-10 核实后推翻）

13.2 完工时曾计划「紧接本役把四个章节接回既有引擎、删掉重复实现」。**三路逐配对核实后，这条计划的前提是错的**——当时那张「report_engine 是个平行宇宙」的对照表有一半是从 import 清单**推断**的，没有逐行验证。核实结论：

| 原以为的重复 | 核实结论 |
|---|---|
| `report_market` → `cockpit_engine/aggregator` | **❌ 证伪**。`aggregate(symbol, light=)` 是**按单只股票**做五维打分，压根不做市场总览，两者语义零重叠。真正的重复对象是 `web_searcher` 的指数/板块/资金流三路 vs `agents/tools/market_tools.py`（**打同一个东财端点**），收敛点在 13.4-2 的 `acquisition/`，不在 cockpit |
| `report_picks` → `recommend_engine` | **❌ 不是重复，是漏斗的两级**。A（报告侧）吃报告窗口内全部 BUY 信号，七维**纯技术面**规则打分（共振33%/盈亏比20%/…/庄股7%），廉价给全市场排序再富化 top-10；B（选股侧）先用「主板+去ST+**买得起**+ROE≥8」砍到 ≤8 只，再逐只跑 cockpit 五维深评。**B 有账户可负担性+风控+可下单股数（A 完全没有）；A 有庄股风险维+回测加权+喂长 prompt 的富化字段（B 完全没有）**。B 的 `buys` 缺 A 的 prompt 所需的一大半字段，喂不动。删任一套都丢能力 |
| `report_news` → `news_engine` | **⚠️ 数据层与 BERT 早就共用了**（`agents/subagents/news.py:41` 已在调 `web_searcher._collect_all_news`；两边同一个 `SentimentAnalyzer` 单例）。没共用的只有**成稿层**：Ch3 有宏观/国际/行业三段式硬规则 + `_CRITICAL_KEYWORDS` 重大新闻高亮 + 跨章节上下文，`build_report_prompt` 是另一套更浅的 5 段。硬合会让报告掉档 |
| `report_strategy` 的 Ch6 → `review/service` | **❌ review 不做前向归因**（它是「单日横截面 + AI 教练打分」，且读 `PendingOrder` 而非 `DecisionLog`）。Ch6 那 220 行回算真正的孪生兄弟是 `analysis_engine/signal_tracker.py`，但**记录集不同**（ST 只装 `Signal` 行，不装 `report_picks`）**且口径三处不同**：先触发互斥(A) vs 双 flag 独立(ST)、窗口不封顶(A) vs 20 日封顶(ST)、有效价单一收益(A) vs 固定 N 日收益+MFE/MAE(ST) |

**所以「接引擎」不做。** 真正该做的两件事各有归宿：
1. **抓取重复** → 13.4-2 `acquisition/`。实锤：东财 `qt/ulist.np/get`（指数快照）有 **5 份**实现、`qt/clist/get`（板块榜）有 **6 份**。`web_searcher.py` 已是事实上的全站抓取中枢（news_engine / news_tools / news subagent / api.routes.news / advisor_engine / report 六处依赖），整体迁入 `acquisition/` 时必须保留全部公开方法签名。
2. **Ch6 回算重复** → 第 14 步的 **P0-1「DecisionLog outcome 回填」**（`docs/14` §P0-1）。给 `DecisionLog` 加 `outcome_5d/outcome_20d/hit_stop/hit_target/outcome_status` 字段 + 照抄 `SignalTracker.update_all` 的回填骨架，让 Ch6 读**已持久化**的字段而非每次报告现算。需动 DB schema，故不在第 13 步。
